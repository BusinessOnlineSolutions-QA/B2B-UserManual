Admin Console Utility Services Master

This module is used to configure service charges and retailer commissions for all standard transactional services such as Recharge, BBPS, AEPS, and DMT. The settings defined here directly control how transactions are charged and how retailers earn.

Purpose of Utility Services Master

Utility Services Master allows administrators to define pricing rules for services. These rules can be applied globally to all retailers or customized for individual retailers.

Important: Charges and commissions configured here are applicable only to non-travel services. Travel-related commissions are configured separately under Admin Console → Travel Services Master.

How This Module Works

User Guide

Before creating or editing any service charge or commission, it is important to understand the logical flow of this module. The steps below explain how the system processes your selections.

Step 1: Select User

The Select User field determines who the charges and commissions apply to.

  • All Retailers – Sets default charges and commission for every retailer in the system.
  • Specific Retailer (e.g., Retailer ABC) – Sets custom charges only for that retailer.
Example:
You set Recharge commission as 2% for All Retailers.
Later, you set 3% for Retailer ABC.
→ Retailer ABC receives 3%, all others receive 2%.

Step 2: Select Product & Service Details

After selecting the user, the Product field displays only the services that are enabled for that user.

  • When user is All Retailers, all admin-enabled services are shown.
  • When a specific retailer is selected, only that retailer’s enabled services appear.
Example:
Retailer XYZ has only Flight enabled.
→ Recharge and BBPS will not appear in Utility Services Master for XYZ.

Step 3: Payment Type & Mode (Where Applicable)

These fields are enabled only for services where payment behavior differs, such as Payout and Payment Gateway.

  • Type of Payment – Debit Card, Credit Card, UPI, Net Banking, Wallet, etc.
  • Mode of Payment – IMPS / NEFT / UPI for payouts, or Visa / Master / RuPay for cards.

Step 4: Category, Type & Operator

Some services are further divided into categories and operators. These fields help apply charges more precisely.

  • Contain Category – Enables category selection (Yes / No).
  • Type – Example: Mobile or DTH under Recharge.
  • Operator – Airtel, Jio, VI, BSNL, etc., based on selected type.

Step 5: Define Slab Range

All charges and commissions are configured using amount slabs. A slab defines the transaction range where specific rules apply.

  • From Amount – Starting value of the slab
  • To Amount – Ending value of the slab
Example:
From Amount: ₹251
To Amount: ₹1000
→ Any transaction between ₹251 and ₹1000 uses this slab.

Step 6: Service Charge & Retailer Commission

This step defines how much the system charges and how much the retailer earns.

  • Service Charge – Percentage / Amount / Not Applicable
  • Retailer Commission – Percentage / Amount / Not Applicable
Example:
Transaction Amount: ₹500
Service Charge: 1% → ₹5
Retailer Commission: 0.5% → ₹2.50

Editing Existing Slabs

Existing slabs can be edited from the same page. The displayed data depends on the selected user.

  • Selecting All Retailers shows only global/default slabs.
  • Selecting a specific retailer shows slabs created for that retailer only.
Best Practice: Prefer editing slabs instead of deleting them to maintain audit consistency.

Admin Console Travel Services Master

This module is used to set / edit service charges and retailer commissions for travel services such as Flight and Bus. It works the same way as Utility Services Master, but it applies only to travel-based products.

Purpose of Travel Services Master

Travel Services Master allows the admin to define how much to charge and how much commission to provide to retailers for travel bookings. You can configure rules as a default for all retailers or override the rules for a specific retailer.

Important: Travel commissions/charges are configured here only (Flight / Bus). For Recharge, BBPS, AEPS, DMT, etc. use Admin Console → Utility Services Master.

How This Module Works

User Guide

Follow the steps below to set travel service charge and commission correctly. The fields shown on screen change based on the selected Product Source (Flight or Bus).

Step 1: Select User Type (Fixed)

User Type indicates which panel scope this commission setup belongs to: B2B, D2C, or both.

  • If only B2B is enabled: User Type is fixed as B2B.
  • If only D2C is enabled: User Type is fixed as D2C.
  • If both are enabled: You will see a dropdown to select B2B or D2C.
Note: This is panel-to-panel dependent. If your panel has both services, always confirm you’re configuring the correct scope.

Step 2: Select Retailer Type

Retailer Type decides whether you want the configuration to apply to all retailers (default) or only to one retailer (custom rule).

  • All Retailers: Sets the default rule for everyone.
  • Specific Retailer: Sets a custom rule for one retailer only.
Example:
Default Flight commission is ₹20 for All Retailers.
For Retailer ABC you set ₹30.
→ Retailer ABC gets ₹30, others remain on ₹20.

Step 3: Retailer ID (Only for Specific Retailer)

Retailer ID is enabled only when Retailer Type is selected as Specific Retailer. Select the retailer you want to configure.

Tip: Always double-check the Retailer ID before saving, to avoid wrong commission mapping.

Step 4: Select Product Source (Flight / Bus)

Product Source decides which travel service you are configuring. Travel products typically include Flight and Bus.

  • Flight → shows flight-specific fields like Air Category and Operator.
  • Bus → shows bus-specific fields like Bus Category and Seat Type.
Best Practice: Configure defaults (All Retailers) first for both Flight and Bus, then apply retailer-specific overrides only when required.

Flight Fields (Visible only when Product Source = Flight)

When Product Source is set to Flight, the following fields become available:

  • Air Category: Domestic / International
  • Operator ID (Airline): Based on the air category, the airline list is filtered or can be set to ‘All Operators.’
Example:
Product Source = Flight → Air Category = Domestic
→ Operator list shows only domestic airlines (Air India, IndiGo, etc.).

Bus Fields (Visible only when Product Source = Bus)

When Product Source is set to Bus, the following fields become available:

  • Bus Category: AC / NON-AC
  • Seat Type: Sleeper / Seater
Example:
Product Source = Bus → Bus Category = AC → Seat Type = Sleeper
→ Your charge/commission applies only for AC Sleeper buses as configured.

Step 5: Configure Service Charges & Commission

This is the core pricing configuration. You can set both the Service Charge (deducted/charged) and the Retailer Commission (earning for retailer).

  • Service Charge Type: Percentage / Amount / Not Applicable
  • Service Value: The charge value based on selected type
  • Retailer Commission Type: Percentage / Amount / Not Applicable
  • Commission Value: Commission value based on selected type
Examples:

Example A (Amount):
Service Charge Type = Amount, Service Value = ₹10
→ ₹10 will be charged/deducted as service charge for that travel transaction rule.

Example B (Percentage):
Retailer Commission Type = Percentage, Commission Value = 0.50%
→ Retailer earns 0.50% commission as per your travel transaction rules.

Step 6: Save, Search, and Edit

After saving a rule, you can use the module’s listing/search to find the same configuration and edit it anytime. This helps maintain travel pricing without deleting existing setups.

  • Create: Add a new rule for Flight/Bus.
  • Search: Filter rules by retailer/product/category/operator.
  • Edit: Update service charge/commission and save changes.
Recommendation: Prefer Edit over deleting rules to keep configuration continuity and reduce mistakes.

Admin Console Manage Subscription

This module displays the subscriptions under which the Admin panel is onboarded. It is one of the most critical control modules of the system, as it governs service availability and subscription-based access for all retailers.

Purpose of Manage Subscription

Manage Subscription is not limited to viewing subscription plans. From here, the admin controls which subscriptions are active, which features are linked, and how much retailers are charged on a monthly / quarterly / half-yearly / yearly basis.

Critical Note:
Any change performed in this module directly impacts retailer service access. Please proceed carefully.

How This Module Works

Follow the steps below to correctly manage subscriptions and linked features. Incorrect configuration may immediately affect all downstream retailers.

Critical Module

Step 1: View Subscription List

When you enter this module, you will see a list of all subscription plans under which the system is onboarded.

  • Subscription Name
  • Subscription Status (Active / Inactive)
  • Linked Features

Step 2: Activate / Deactivate Subscription

Admin can activate or deactivate a subscription directly from the list. This action has a platform-wide impact.

Critical Warning:
  • Deactivating a subscription affects all retailers mapped to it.
  • All services/features under that subscription are terminated.
  • Retailers will be unable to use those services further.
Best Practice:
Always verify retailer dependency before deactivating any subscription.

Step 3: Link Feature

Each subscription has a Link Feature option. This is used to map services/features and define subscription pricing.

  • For first-time setup, the linked feature list may appear empty.
  • Click + Link New Feature from the top-right corner.

Step 4: Select Feature & Set Pricing

When linking a feature, the admin must configure subscription charges for different billing cycles.

  • Feature: Dropdown showing all services/features the admin is onboarded with.
  • Subscription Charges:
    • Monthly
    • Quarterly
    • Half-Yearly
    • Yearly
Example:
Feature: Travel Services
Monthly: ₹499
Quarterly: ₹1,299
Half-Yearly: ₹2,499
Yearly: ₹4,999

Step 5: Save, View, and Manage Linked Features

After saving, the linked feature will appear under the subscription. From here, the admin can manage existing feature mappings.

  • Edit subscription pricing
  • Deactivate individual features
  • Review linked services
Important:
Deactivating a linked feature will immediately disable that service for all retailers using this subscription.

Step 6: Retailer Assignment (Downstream Usage)

The configuration done in this module is used later under: Membership → Manage Retailer.

  • Admin assigns subscriptions to retailers
  • Retailer services are enabled via linked features
  • Charges apply as per subscription pricing
Flow Summary:
Manage Subscription → Link Feature → Assign to Retailer → Retailer Uses Services

Admin Console Bank Master

This module is used to insert and manage the Admin’s bank accounts. These accounts are displayed on the Retailer side, so retailers can send money to the admin account and then raise a Make Payment Request.

What is Bank Master used for?

Bank Master is the central place where the admin maintains the list of receiving bank accounts. These bank details are visible to retailers inside: Make Payment → Make Payment Request.

Retailer-side Usage:
Retailers use these bank accounts to deposit money and then create a Make Payment Request. After admin approval, the retailer wallet is credited.

Retailer Payment & Wallet Credit Flow

This section explains how retailers pay the admin and how those funds are credited back to the retailer wallet.

Retailer Payment Methods:
  • Scan QR / Pay via VPA (if QR/VPA is enabled on that bank account), then raise a Make Payment Request
  • Direct Transfer to the bank account, then raise a Make Payment Request with payment details
Example:
Retailer scans the QR and pays ₹5,000 → then raises a Make Payment Request with the payment reference/UTR.
How Funds Are Credited to Retailers:
  • Approve Make Payment Request:
    Retailer submits payment proof. Admin verifies and approves it from Make Payment → Make Payment Approval .
  • Direct Wallet Transfer:
    Admin can directly credit the retailer wallet from Manage Wallet → Wallet Transfer , if the payment has already been verified offline.
Example:
Retailer paid via bank transfer and shared UTR on call → Admin verifies from bank statement → credits wallet using Wallet Transfer.
Best Practice:
For audit, reconciliation, and tracking, always prefer Make Payment Approval whenever the retailer raises a formal request.

Admin Module Campaign Control Financial Impact

This module is used to create and manage promotional campaigns (promo codes) for retailers. Promo codes can be configured based on geography, user eligibility, services or wallet top-up, and usage limits. All active and inactive promo codes are listed here and can be searched, edited, activated, or deactivated.

Primary purpose
Create promo campaigns that reward retailers when they achieve a configured volume/target within a defined time window.
Eligibility logic
Promo eligibility is volume-based. Retailers must achieve the configured target volume (transaction volume/target) during the campaign period to redeem the promo benefit.
Example (Volume-based promo):
Service: Recharge
Campaign: 01 Jan 2026 → 15 Jan 2026
Target volume: ₹70,000 transactions
→ Only retailers who achieve ₹70,000 target within this period can redeem the promo benefit.
What you must verify
Validity (start/end), Status (active/inactive), limits (per user + total), and service/operator selection (wrong scope can cause incorrect eligibility and financial loss).
Where to cross-check
Use Report → Transaction Report to verify transactions during the campaign window and confirm volume achievement (audit / support verification).
Note: When this module is opened, all active and inactive promo codes are visible. You can filter them using criteria such as Retailer Code and campaign details.

What is Manage Promo Code used for?

The Manage Promo Code module is where the admin creates promotional campaigns (promo codes) which will be visible to retailers. These promos are volume/target based, meaning retailers must achieve a configured target during the campaign period to redeem the promo benefit.

Example (Volume Target):
Create a promo on Recharge from 01 Jan 2026 to 15 Jan 2026 with target volume ₹70,000.
Only retailers who achieve the target within this window can redeem the promo.

Configure who the campaign applies to and the promo’s discount definition. (Promo eligibility is volume/target based as per your campaign rules.)

Select whether the promo applies on Website, Mobile Application, or Both.

3) User Eligibility

Define the eligibility rules and limits. Campaign eligibility is volume-based, so ensure your rules support the target logic.

User Type
Choose whether the promo is for All Users, New Users, or Existing Users.

Minimum transaction value required for a transaction to be considered eligible.
Max Cashback
Maximum cashback/benefit that can be earned through this promo (cap).
Usage Per User
Number of times a single user (retailer) can avail this promo code.
Total Usage Limit
Total number of redemptions allowed overall for this promo code (all users combined).

4) Service & Product Selection

Decide whether this promo is for services or for wallet top-up. Only one of the two can be selected per promo.

Promo for Services
The service list shows only services that the admin has taken.

You can create promos at multiple levels:
  • Service level: e.g. all BBPS services.
  • Category level: e.g. BBPS → Electricity only.
  • Operator/biller level: e.g. BBPS → Electricity → BSES RAJDHANI PVT LTD.
In the last example, the promo will apply only to Electricity bills of BSES RAJDHANI PVT LTD.
Promo for Wallet Top-up
Promo is applied on wallet top-ups. When a retailer tops up their wallet with configured amounts/conditions, they become eligible as per promo rules.

5) Validity & Additional Settings

Control when the promo is active and how it is described.

Start Date & Time
When the promo campaign starts (volume is counted only within the valid time window).
End Date & Time
When the promo ends. After this date/time, it is no longer applicable.
Status
Define whether the promo is active now or inactive.
Can be changed later during the campaign (pause/stop/manual activation).
Campaign Description
Internal description for the promo code (reason, terms, internal notes).

Important Campaign Rules

  • Promo eligibility is volume-based: set the campaign window and target correctly.
  • Always set clear and correct validity dates (Start / End) before activation.
  • Ensure correct service/operator selection when creating service-based promos.
  • Incorrect discount configuration may cause direct financial loss.
  • Review Min Order Value, Max Cashback, Usage Per User, and Total Usage Limit carefully before launch.
